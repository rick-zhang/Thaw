# macOS 27 适配进展

继续使用原来的显示、隐藏、永久隐藏三个区域，不用应用列表替换布局页。当前为实验性适配，尚不能视为与 macOS 26 功能完全一致。

## 已接入的路径

| 功能 | macOS 27 的处理方式 |
| --- | --- |
| 项目发现 | 枚举各应用的辅助功能菜单栏元素，后台扫描有超时和取消处理。 |
| 项目标识 | AX 元素使用独立视图标识；同应用、同名元素分配实例编号，避免搜索、快捷键和 Thaw Bar 合并项目。 |
| 布局分区 | 拖放、右键菜单和辅助功能操作共用分区路径，同一应用的多个图标一同归类。 |
| 打开项目 | 布局、搜索、热键和 Thaw Bar 使用 AXPress，先解除隐藏，避免向空窗口编号发送事件。打开后保持展开，可通过 Thaw 按钮收起。 |
| Thaw Bar | 恢复按显示器设置选择 Thaw Bar 的入口，使用菜单栏捕获图像；尚无有效预览时回退应用图标，支持左键打开。 |
| 分区边界 | 隐藏项目展开后自动移到显示项目左侧，保留两组内部的相对顺序。跨区调整及展开期间的扫描会重新核对边界；鼠标拖动期间不干预，失败后延迟重试。 |
| 区域内排序 | 原布局拖放、左右移动及按名称排序接入 Command 拖动，使用 MenuBarAgent 宿主位置，移动后重新枚举并检查实际相邻关系。 |
| 图标预览 | ScreenCaptureKit 捕获宿主窗口，按宿主坐标裁剪；可见图标实时刷新，隐藏图标保留最后有效预览，展开后更新。 |
| 配置保存与恢复 | 新配置独立保存应用分区；旧配置按应用合并，相同应用的冲突采用更严格的隐藏区域。按稳定标识恢复区内顺序，并读取宿主坐标确认结果；无法定位或确认时提示部分失败。 |
| 条件触发器 | 分区移动接入新版路径，临时结果不写入用户布局；释放触发器后恢复保存的分区，同应用仍有其他触发器时不提前恢复。 |
| 缓存刷新 | 清理已退出应用及完整扫描后消失的可见项目；隐藏或未完成扫描的项目保留以便恢复。 |
| 请求管理 | 合并相同的隐藏请求；失败、取消、超时均完成回调，避免分区事务一直处于忙碌状态。 |
| 启动与更新 | 不再显示 macOS 27 启动警告，但保留该系统的 Alpha 更新入口。两者不再共用阈值。 |

新版分区通过 `Defaults.store` 保存在 `macOS27SectionAssignments`，配置文件对应可选字段 `macOS27Assignments`。旧文件不需要此字段即可解码，不覆盖 macOS 26 的旧窗口布局记录。

系统图标保持不可拖动，不卸载系统菜单项，也不修改其系统设置。Option 单击及双击继续遵循原有偏好设置。

## 尚未解决的问题

- 分隔线仍未接入；布局重置已改用新版分区事务，不再依赖旧分隔线窗口。
- 同一应用发布多个图标且缺少唯一 AX 标识时，不猜测宿主对应关系；这类项目的捕获或排序可能不可用。系统固定图标仍不参与排序。
- 隐藏图标不再由宿主渲染，因此隐藏期间不持续更新图像；展开后恢复实时更新。图像比较及闪烁检测已接入可见图标的新鲜捕获；隐藏、溢出或捕获失败时不使用旧预览作为检测输入。预览需要屏幕录制权限，分区和排序需要辅助功能权限。
- 隐藏限制按应用生效且影响所有显示器，不能单独隐藏同一应用的某一个图标。
- 旧配置中的逐项目标识可能与新版不同，逐项目快捷键可能需要重新绑定。新版配置支持分区与区内顺序恢复；旧标识无法匹配的项目、尚未启动的项目不会强行定位。后启动项目的配置顺序补排仍未接入。
- 代替其他应用执行右键点击尚不支持，应在系统菜单栏中操作。
- 打开隐藏项目后仍保持展开，尚未接回旧版菜单关闭后的自动收起流程。
- 新版状态项目的扩展界面键盘会话、多显示器菜单栏外观及间距仍需进一步实机验证。[Apple 的扩展界面接口](https://developer.apple.com/documentation/appkit/nsstatusitem/expandedinterfacedelegate) 管理应用自身状态项目的自定义窗口生命周期，不能据此推断可控制其他应用的排序。

隐藏接口是运行时加载的私有 `MenuBarClientCore` 接口，有能力检查、失败和超时处理，但系统更新可能改变接口。该限制会影响通知中心；隐藏期间如需使用通知中心，先展开所有隐藏区域。这不是 TCC 授权问题，不需要反复重置权限。

接口调用方式参考 [MenuBarHider 的实现](https://github.com/happy666End/MenuBarHider/blob/main/MenuBarHider/Services/MenuBarAgentBridge.swift)，MIT 许可保存在 `docs/licenses/MenuBarHider-MIT.txt`，并纳入应用致谢。

### 新菜单栏项目的默认位置

macOS 27 已接入“新菜单栏项”拖动标记。把标记拖到目标区域和图标之间，后续新应用的菜单栏项目会进入该区域；单图标应用插入标记记录的邻居左侧或右侧，多图标应用保留系统内部位置并支持手动排序。锚点消失时回到该区域的默认边缘；系统固定项目不自动移动。同一应用新增图标继承该应用现有分区，避免整组被意外搬动。

首次升级只登记当前运行应用的现有项目，不重新分配已有布局。项目稳定标识和待完成的放置队列分别保存在隔离存储支持的 `macOS27SeenItems`、`macOS27PendingNewItems`，已有保存分区的应用重启不会重复认定为新项目；仅历史登记过、尚无保存分区的应用在 Thaw 运行期间重新启动时，仍会进入默认放置队列。Thaw 启动时已经运行的已登记应用保持原位置。未完成扫描的初始进程继续作为迁移基线。用户手动调整或恢复配置会取消相应的待处理放置。

隐藏区域内的定位需要临时展开菜单栏，完成后恢复原展开状态。无法可靠取得宿主坐标时先保存分区，并延迟重试位置调整；不把预期位置冒充系统已完成的排序。

本轮新增 5 项测试覆盖首次迁移、延迟扫描、重启去重、队列恢复、同应用分区继承及锚点规则。全量 3341 项测试中，现有 `HookRunnerTests.timedOutHookLeavesNoDescendants` 因临时文件未生成失败；包含该套件和新版菜单栏套件的 38 项复跑全部通过。日志分别为 `build/local/macos27-new-items-tests.log`、`build/local/macos27-new-items-retest.log`，安装日志为 `build/local/macos27-new-items-install.log`。

临时测试应用实测已被识别为新项目，保存为显示区域，完成放置队列；布局页显示它在输入法项目左侧。宿主探针未稳定读取到测试应用对应元素，因此不把这一观察作为完整的物理位置验收。隐藏区标记拖动的实机验收尚未完成：验收时用户正在编辑配置，为避免干扰，保留了原标记位置，并退出临时测试应用。

### 隐藏项目左侧边界验证

展开隐藏区域时，自动把可定位的隐藏项目移到显示项目左侧；跨区调整及展开期间的扫描继续维护边界，不新增开关。排序保留当前组内相对顺序，不移动显示组来实现边界。系统溢出或缺少唯一宿主坐标的项目暂时跳过，避免阻断其他项目；其后能定位时再处理。

2026-09-29 在两块显示器上，通过布局的“展开所有项目”实测各 14 个隐藏项目，隐藏组最右边界与显示组最左边界分别为 1442.5、1074.5 点。收起后再次展开，边界和各屏隐藏项目相对顺序均保持一致。当前 QSpace 的项目没有可匹配宿主坐标，不纳入这一验收结论。原“智能自动重新隐藏”偏好在验收结束后已恢复。

证据为 `build/local/probes/menuhost-boundary-final.log`、`build/local/probes/menuhost-boundary-reexpanded.log`。本轮全量回归 3335 项通过，补充边界测试及最后调整后的专项回归 13 项通过；1484 条字符串通过中文检查。日志为 `build/local/macos27-boundary-tests.log`、`build/local/macos27-boundary-focused-tests.log`，最终 arm64 Release 安装日志为 `build/local/macos27-boundary-install.log`。

### 原有功能复盘与补齐

- 配置恢复：复用区域内 Command 拖动事务，等待排序及隐藏状态恢复，再处理下一分区。每次移动后检查相邻关系，结束时再核对整区顺序。未记录的新项目保持相对顺序，系统固定项目仅作锚点。分区恢复成功但排序失败会明确提示，不将目标数组写成实际位置。
- 布局重置：恢复显示、隐藏、永久隐藏三个目标入口；按应用提交新版分区，覆盖暂未运行应用的旧分区，排除系统应用和 Thaw。仅在系统确认分区事务成功后清理旧排序、固定分区及新项目标记偏好。
- 存储隔离：配置快照和触发器释放恢复统一读取 `Defaults.store`，不再绕过测试隔离读取真实偏好。
- 图像条件：参考图像及运行时比较改用宿主窗口捕获；只返回本次新鲜采样。闪烁检测接收同一批真实图像，没有打开设置页时也按触发器需求采样。隐藏、溢出、移动中或捕获失败的图标清除相应检测历史，保留布局预览但不拿预览触发规则。简繁中文提示已同步。

这轮代码补齐不等于全部实机验收。仍需验证配置切换后的系统物理顺序、三个重置目标，以及可见图标的参考采集和闪烁触发。为避免改写正在使用的配置，不自动对当前布局执行重置。

验证：全量 3343 项测试、378 个套件通过（`build/local/macos27-review-verified-tests.log`）；最后的排序容错调整后，15 项专项回归通过（`build/local/macos27-review-order-tests.log`）。1484 条字符串通过简繁中文检查。新版功能的系统交互验收仍按上一段列出的范围执行，单元测试不替代实机验收。

本轮 arm64 Release 已通过 `./scripts/install-local.sh` 安装到 `/Applications/Thaw.app`，严格递归签名校验通过，并确认从该路径启动。安装日志：`build/local/macos27-review-install.log`。

### 历史登记阻断新启动应用定位的修复

Docker Desktop 曾存在 `macOS27SeenItems` 记录，但没有保存分区或待定位任务。旧实现仅检查稳定标识是否首次出现，会在再次启动时跳过默认放置。现在额外记录当前会话观察到的进程：运行期间新到达且没有保存分区的应用可重新入队；进程先启动、菜单栏图标延迟出现也能处理。已保存布局的应用及 Thaw 启动时已有项目保持原位置。放置仍通过宿主坐标和 Command 拖动验证。

该修复在后续启动应用时生效，不批量搬动当前已运行项目，也不清空用户的历史发现记录、分区或权限。

回归验证：22 项专项测试通过，包含历史已见应用再次到达、延迟出现图标、默认显示/隐藏区域、重复扫描去重和已有布局保护。日志：`build/local/docker-placement-final-tests.log`。Docker 实际重启后的物理位置尚待实机验收。

### 新项目放置延迟优化

macOS 27 的启动通知增加独立定向扫描：只扫描新进程，发现图标后停止；最多重试 5 秒，间隔 200 毫秒，之后交回普通轮询。该路径不等待原有 1 秒防抖，也不更新全量扫描的时间戳，避免漏扫其他应用。局部扫描继续保留其他进程的缓存。可见新项目直接使用宿主位置，跳过展开隐藏区及 250 毫秒等待；自动放置先使用约 186 毫秒的拖动事件序列，未通过实际相邻校验时回退约 474 毫秒的常规序列。上述为代码设定的等待时间，不是实测端到端延迟。

当前仍需系统先创建可定位的菜单栏项目，之后才能移动；不能保证首次绘制就位于目标位置，实际移动观感仍需实机验收。

本轮发现、定位、排序与隐藏策略共 27 项专项测试通过，日志：`build/local/new-item-latency-tests.log`。启动到移动完成的实际耗时与视觉效果尚未实测。

### 多图标应用的顺序保护

已识别应用的 AX 标识可能从 `Item-0` 变成具体模块标识，旧逻辑会误将其作为新项目自动放置。现在以扫描开始前的应用发现记录判断：已有应用的标识更新或模块新增只继承分区，不因新标识再次执行默认定位；此前未保存分区的单图标应用重新启动仍保留默认放置支持。

多图标应用不再逐项自动插入区域边缘，旧版留下的相关待放置队列也会清理。这样避免按标识排序再依次插入导致内部顺序改变；分区、用户手动排序和明确应用配置的排序仍保留。此策略保留系统实际内部顺序，不能自动还原此前已经改变且未保存的顺序。用户主动按名称排序或应用配置仍会调整顺序，应用自身重建菜单栏项目也可能影响系统顺序。

顺序保护专项回归：29 项测试通过，覆盖 iStat 通用标识升级、旧标识待办清理、多图标队列保护，以及 Docker 单图标定位兼容。日志：`build/local/istat-order-final-tests.log`。iStat 长时间运行及模块重建后的系统物理顺序仍待实机观察。

### 临时身份与稳定身份关联

菜单栏身份不再使用枚举序号 `Item-N` 作为新匿名项目的持久键。新匿名项目获得独立临时 UUID；同一进程内，通过 AX 元素双向唯一相等关系沿用内部 tag，枚举顺序、标题或位置变化不影响它。UI 展示身份也使用该 tag，避免索引改变造成视图互换。

后续出现同应用内唯一的真实 AXIdentifier 时，将该稳定标识关联到原 tag，保存到隔离存储支持的 `macOS27IdentityAliases`。不改写原 tag，因此自定义名称、快捷键、配置顺序、分组、标记锚点和待定位任务中已有的标识引用继续有效；应用重启后可通过真实标识恢复该关联。稳定标识短暂缺失但 AX 元素仍一致时保留原身份。同 bundle 多进程的定向扫描一起处理，避免把重复标识误认成唯一。

不按标题、坐标、枚举序号或“只剩一个项目”猜测关联。重复标识或不完整扫描不建立持久映射，已绑定另一稳定标识的身份不再合并，跨应用或冲突映射不采用。始终匿名且重启后 AX 元素无法确认的项目仍不能跨重启恢复逐项身份；已有历史 `Item-N` 记录也不会在没有现场证据时批量迁移。

### 手动排序的跳动优化

布局区内拖放和单步移动会传递实际被移动的项目。当其他项目的相对顺序一致时，只移动该项目；复杂顺序恢复仍走整区路径。已经满足目标顺序时不再发送拖动事件。排序先读取实际宿主位置，所有目标均可定位时省去隐藏区展开与收起；需要展开时仍等待排序与隐藏状态恢复。

手动排序共用快速拖动：事件序列约 186 毫秒，实际相邻关系未通过校验时回退约 474 毫秒的常规拖动。系统实际顺序仍会再次确认。此数值是事件等待时间，不是端到端耗时；不承诺完全消除系统动画，隐藏项目仍需先展开。
